# Matching contract

`configs/cwe_catalog_v1.json` freezes all 969 weaknesses and 422 categories from the [MITRE CWE 4.20 release](https://cwe.mitre.org/data/archive/). The scope includes deprecated entries and excludes taxonomy views; categories preserve coarse annotation targets. The archive hash, release date, copyright and redistribution terms are saved with the catalog. No dataset annotations select its entries. The two NVD metadata markers (`NVD-CWE-Other`, `NVD-CWE-noinfo`) are unknown annotations, not CWE candidates. The catalog is checked in independently of training/evaluation annotations. Changing its scope requires an explicit new catalog version and a full rerun. Annotated training CWEs outside its scope cause preparation to fail; missing or invalid embeddings also fail.

| Labeled function | Real annotated CWE | Other real CWE | NONE |
|---|---|---|---|
| Vulnerable, known annotations | Match (all annotations) | No match | No match |
| Benign | No match | No match | Match |
| Vulnerable, unknown annotations | No pair target | No pair target | No pair target |

Adapters retain every real CWE in a semicolon-separated `cwe_id`. Deduplication unions annotations for identical labeled functions and rejects conflicting vulnerability labels. NONE is a learned model parameter and is stored with the checkpoint, alongside the fixed real-CWE embeddings. Neither a missing embedding nor absent metadata produces a NONE representation or benign label.

Vulnerable samples without a real CWE are written to `unknown_cwe_vulnerable.csv` during normalization and excluded from supervised training preparation. Their count is recorded; they are never relabeled benign. External unknown-CWE vulnerable samples retain their positive binary labels and enter function-level metrics, but have no retrieval target. Benign samples are retained even without annotations. This scope restricts internal binary evaluation to the prepared corpus; the report must not imply coverage of excluded unknown vulnerable functions.

Each training row uses all annotated positives (or NONE for benign), a seeded random incorrect candidate or the highest-scoring incorrect candidate, and an obligatory NONE negative for annotated vulnerable rows. Positive and negative BCE groups are averaged equally per function; triplet loss is added with the recorded weight. Hard mining ranks **pair-head logits**, excludes all positives, and breaks ties by catalog order. CWE numbers carry no notion of semantic distance. Function and graph encoders run once per batch; candidate head scoring is chunked.

`pair`, `graph_pair`, `triplet_random`, `triplet_hard` replace the ambiguous E0–E4 matching settings. The prior code configured E2 as triplet-only while reporting terminology suggested wrong-CWE classification; E4's hard negatives used numeric proximity. Neither old label establishes a valid comparison with the new pair-supervised contract. Historical graph-fusion E2/E4 names referred to different experiments entirely. Resolved settings, rather than those names, define new runs.

The decision score is `max(real CWE logits) − NONE logit`. A function is vulnerable when this margin is **strictly greater** than its validation-calibrated threshold; otherwise it predicts NONE. Real-CWE ties use fixed catalog order. The top real CWE is returned for a vulnerable decision; top-3 retrieval reports an intersection with any annotated correct CWE. Retrieval is measured only on annotated vulnerable rows, including catalog misses as misses, with support reported.

Checkpoint selection uses complete-catalog validation PR-AUC at a fixed epoch budget. After selection, full-precision inference scans the complete catalog on validation data. Calibration chooses the threshold with maximal F1 across observed margins, breaking ties toward the larger threshold. Only the selected weights are calibrated. Calibration, checkpoint identity and validation support are saved; final tests, exports, external evaluation and the demo use that persisted threshold unchanged. Historical uncalibrated checkpoints are rejected.

Graph vocabularies are built from training functions only. Unknown external/validation AST node types map to a dedicated `<UNK>` ID. The same parser and frozen vocabulary encode external functions and demo inputs. These graphs have AST parent-to-child edges; they do not contain CFG or PDG edges. External evaluation removes normalized-code overlaps with the whole internal corpus and duplicate external functions, and records removed counts. PrimeVul test is not an independent external benchmark for PrimeVul training; the default external stress test is DiverseVul.

Prediction manifests record code revision/dirty state, immutable dataset revision, preparation hashes, catalog version, graph vocabulary hashes, resolved configuration, seed, checkpoint hash and calibration threshold. Each export records its row count and hash. The canonical report verifies these identities and counts, rejects historical artifacts and duplicate run/split exports, and generates all metrics from the same CSVs. Unseen splits are diagnostic subsets that may overlap ordinary test/validation exports; counts are not added across these slices.
