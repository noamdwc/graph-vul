# Operating instructions

Use Python 3.12. Dependencies are pinned to the verified local CPU environment. CUDA installs of PyTorch are selected for the training host; Colab provides the GPU driver.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
HF_HUB_OFFLINE=1 WANDB_MODE=disabled python -m pytest -q
```

CPU CI runs the same checks without downloading pretrained weights. Contract pilots use a deliberately small synthetic encoder; they establish data flow, supervision, persistence and artifact consistency, not real-model performance.

## Local preparation

Every preparation or run writes a **new** directory. Reusing one fails instead of silently mixing artifacts. The pinned PrimeVul revision used for this rerun is:

```bash
python -m graph_vul.pipeline.prepare_matching \
  --output-dir data/interview-v1 \
  --dataset-revision 4fd7158322872d711e90f091dbd8673ef32cb1be
python -m graph_vul.pipeline.embed_cwe \
  --input configs/cwe_catalog_v1.json \
  --output data/interview-v1/cwe_embeddings
```

Preparation reruns normalization and the existing subset filters, produces project-disjoint splits, checks project and normalized-code leakage, and extracts AST graphs with training-only vocabularies. It records excluded unknown-CWE vulnerable rows separately. CWE description embedding uses the existing DeBERTa encoder. Keep normalized.csv, subset.csv, preparation.json, subset reports, splits, graphs and CWE embeddings together.

For DVC orchestration, `dvc repro` uses these stages under `data/interview-v1`. Existing `dvc.lock` belongs to the historical workflow and must be regenerated by a completed rerun, never treated as new experiment evidence. Install DVC separately (`pip install 'dvc>=3.30,<4'`) if using that optional orchestrator.

To rebuild the checked-in catalog from its independent source (no dataset input):

```bash
curl --fail --location --output /tmp/cwec_v4.20.xml.zip https://cwe.mitre.org/data/xml/cwec_v4.20.xml.zip
python scripts/update_cwe_descriptions.py --archive /tmp/cwec_v4.20.xml.zip
```

The builder verifies the exact archive hash before extracting every weakness/category description. MITRE's redistribution terms are retained in `configs/CWE_LICENSE.txt` and in the catalog.

## Colab pilot and training

Upload `data/interview-v1` to `MyDrive/graph-vul/interview-v1`, then open `notebooks/colab_finetune.ipynb` on a GPU runtime. It copies preparation locally, runs the integration pilot first, and saves artifacts to Drive. No model architecture edits are needed in notebook cells.

Equivalent terminal commands:

```bash
python -m scripts.run_matching_matrix \
  --data-root data/interview-v1 --output-dir data/pilot-v1 --pilot
# Inspect the pilot, then run the full shared-seed matrix.
python -m scripts.run_matching_matrix \
  --data-root data/interview-v1 --output-dir data/matrix-v1
```

The pilot runs all four configurations, seed 42, one epoch, four examples per class per internal split, and a fixed random sample of 32 external functions. Its preparation records the complete parent dataset identity and a pilot flag. It exercises the full catalog and artifact flow; its metrics are execution diagnostics and must not be interpreted as performance estimates. Full runs use seeds 42/43/44, 10 epochs, batch size 8, accumulation 8, identical optimizer settings and negative budget. Training selection uses validation PR-AUC; final calibration maximizes validation F1. GPU training uses mixed precision, calibration/export full precision. Reducing the common batch size and increasing accumulation is available if memory requires it; record the change and apply it to all comparison runs.

## Artifact handoff and evaluation

Copy the whole `matrix-v1` directory back locally. Each experiment/seed directory contains `model.ckpt`, `run.json`, prediction CSVs and manifest, external CSVs and manifest. The matrix root contains one canonical report with per-seed and mean/std CSVs. Saved checkpoints carry real-CWE embeddings, NONE, the catalog, AST vocabularies and calibration. Inference still needs cached or downloadable UniXcoder weights/tokenizer to initialize the supported backbone before restoring checkpoint state.

To evaluate a checkpoint again, use fresh output directories:

```bash
python -m graph_vul.export_finetune_predictions \
  --checkpoint data/matrix-v1/triplet_hard-42/model.ckpt \
  --data-root data/interview-v1 --output-dir data/reexport-v1
python -m graph_vul.eval_external \
  --checkpoint data/matrix-v1/triplet_hard-42/model.ckpt \
  --data-root data/interview-v1 --output-dir data/external-v1 --datasets diversevul
python -m graph_vul.analysis.cwe_matching_report \
  --manifests data/reexport-v1/manifest.json data/external-v1/manifest.json \
  --output-dir data/report-v1
```

External normalized inputs are fingerprinted. Dataset loaders are existing Hugging Face adapters; source revision pinning for external downloads is recorded by the adapter. Unknown annotations affect retrieval support but never select candidates. Tests never tune the threshold.

## CLI demo

```bash
python -m graph_vul.demo \
  --checkpoint data/matrix-v1/triplet_hard-42/model.ckpt --function example.c
# Or pipe a C function to stdin.
```

Returns CWE or NONE, the decision margin and saved threshold, NONE logit and top three real-CWE logits. Logits and margins are model scores, not calibrated vulnerability probabilities.

## Historical evidence

Existing `outputs/`, exploratory reports, old data checkpoints and fusion notebooks remain for provenance. They use different targets, candidate inputs, pooling, graph paths or calibration and do not establish results for the current contract. Superseded notebooks are labeled at their entry points. The supported training notebook is `colab_finetune.ipynb`; the supported report is generated from prediction manifests by `cwe_matching_report`.
